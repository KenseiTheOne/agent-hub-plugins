# claude-code — настройки Claude Code для новых сессий и открытые вкладки

Официальный плагин реестра `agent-hub-plugins` (tier `official`). Тип standard, запуск раз в 30 с и сразу по изменению
`~/.claude/settings.json` или файла сессии. Меняет настройки только по вашей кнопке.

Плагин делает работу сам, хаб для него — песочница и права. Решение 10.11: хаб не знает ни Claude Code, ни его
настроек. Всё ниже — в коде плагина: белый список ключей, копия до правки, атомарная запись, набор во вкладку.

## Показывает

- **Базовые для новых сессий** из `~/.claude/settings.json`: модель, effort, стиль ответов, ultracode. Строка шапки
  «Базовые: Opus 5.5 · medium» и плитка поповера — то же одной строкой.
- **Открытые сессии**: каждая живая сессия Claude Code — строка с её состоянием (простаивает, работает, ждёт ответа),
  моделью и effort сейчас. Отличие от базовых — оранжевым; у свободной вкладки — «Привести», у занятой — «после хода»
  или «после ответа».
- **Ход «Проставить базовые»**: что набрано, что ждёт конца хода или вашего ответа, что пропущено и почему. Итог
  остаётся, пока его не уберут.

Откуда что берётся:

| Что | Источник |
|---|---|
| Базовые | `~/.claude/settings.json`: `model`, `modelSettings.<модель>.effortLevel` (для Opus 5.5 и новее действует только он), `effortLevel` (для моделей старше), `env.CLAUDE_CODE_EFFORT_LEVEL` (max), `outputStyle`, `ultracode` |
| Список стилей | встроенные (Default, Proactive, Concise, Explanatory, Learning), `~/.claude/output-styles/*.md` (имя — из заголовка файла), стили включённых плагинов Claude Code (`~/.claude/plugins/installed_plugins.json` → папка плагина в `~/.claude/plugins/cache` → `output-styles/` или `outputStyles` манифеста; имя `<плагин>:<стиль>`) |
| Сессии | `~/.claude/sessions/<pid>.json`: id, папка, имя, состояние, время старта. Сессия живая, если процесс с этим pid жив, начат в то же время (`procStart`, ps в UTC) и это Claude Code |
| Вкладка | `~/.cmuxterm/claude-hook-sessions.json`: surface и workspace сессии (только идентификаторы) |
| Модель и effort сессии | что свежее: файл хаба `$AGENTHUB_CLAUDE_SESSIONS_FILE` (время записи транскрипта, см. «Что нужно от хаба») или то, что плагин проставил сам. Без файла хаба — только второе, а шапка говорит «вкладки: нет данных», а не «как базовые» |

## Чего не читает

- Транскрипты сессий — никогда: там текст переписки. Модель и effort сессий даёт хаб готовыми метаданными.
- Ключи сессий, файлы входа и токены: из `~/.claude/sessions` — только `<pid>.json`.
- Из `~/.claude/settings.json` в выводе только перечисленные ключи. `env`, `permissions`, `hooks` и прочее не
  показываются; тесты кладут в фикстуру маркер в `env` и проверяют, что его нет в выводе.
- Из `~/.cmuxterm/claude-hook-sessions.json` только `sessionId`, `surfaceId`, `workspaceId`, `pid` (`lastBody` с
  текстом не берётся).

## Запись настроек

Пишутся **только** эти пути (`ALLOWED_PATHS` в коде, на каждую операцию — проверка):
`model`, `effortLevel`, `modelSettings.<id модели>.effortLevel`, `outputStyle`, `ultracode`,
`env.CLAUDE_CODE_EFFORT_LEVEL`. Любой другой путь, в том числе `env.ANTHROPIC_BASE_URL`, `hooks`, `permissions`,
`apiKeyHelper`, `statusLine`, `__proto__`, — отказ `not-allowed` (тест «белый список»). Иначе плагин мог бы
перехватить Claude Code.

Как пишется:

1. Прочитать файл. Пустой — как `{}`. Не JSON — отказ `settings-broken`, файл не трогается. Файл — ссылка (dotfiles):
   пишется файл, на который она указывает, а ссылка остаётся.
2. Копия до правки: `~/.claude/backups/settings.json.<время>-agenthub` (права 0600: в ней ваш `env`). Хранятся
   последние 20 таких копий; чужие файлы в `backups` не удаляются.
3. Записать новый текст (отступ 2, порядок ключей прежний, новые — в конец) во временный файл рядом с прежними
   правами.
4. Перед заменой сверить, что файл не поменяли с момента чтения. Поменяли (`/model`, `/effort` в сессии, другой
   плагин) — перечитать и повторить. После трёх попыток — отказ `settings-busy`.
5. `rename` поверх. Запуск действия хаб пишет в журнал.

Особенности Claude Code (проверены по установленной 2.1.321):

- **effort для Opus 5.5 и новее** берётся только из `modelSettings["<id>"].effortLevel`, а `effortLevel` в
  `~/.claude/settings.json` для них не действует (для моделей старше, в том числе 3.x и 4.x, — действует). Плагин
  пишет оба: `effortLevel` и `modelSettings` текущей модели. Модель не выбрана — считается Opus 5.5 (модель по
  умолчанию у API Anthropic): и показ, и запись идут по его записи. При смене модели effort переносится на новую
  модель, иначе она начала бы со своего значения по умолчанию.
- **`env.CLAUDE_CODE_EFFORT_LEVEL`** плагин понимает так же, как Claude Code: уровень (`med` = medium) или max
  перебивает effort во всех сессиях; `auto`/`unset` — у каждой сессии effort по умолчанию её модели; целое число —
  перебивает (показывается как есть); прочее (`ultracode`, пробелы вокруг) Claude Code игнорирует — и плагин тоже.
  Всё, что перебивает, страница показывает оранжевой строкой; выбор уровня это снимает так же, как max.
- **Без выбранной модели** effort базовых — это effort Opus 5.5. Вкладку на другой модели плагин по effort с ним не
  сравнивает: `/effort` в ней переписал бы сохранённый effort её модели.
- **max** в `effortLevel` Claude Code молча выкидывает. Max держится только в `env.CLAUDE_CODE_EFFORT_LEVEL=max`, а
  `env` живые сессии подхватывают сразу. Поэтому max — действие с подтверждением: «действует сразу во всех вкладках,
  включая открытые, и перебивает /effort в них».
- **Уход с max**: `env.CLAUDE_CODE_EFFORT_LEVEL` становится `""` (пусто = «не задано»; `auto` и `unset` значат
  принудительный auto), выбранный уровень — в `effortLevel` и `modelSettings`. Удалённый ключ `env` живые сессии не
  замечают (у них остался бы max), поэтому ключ плагин удаляет сам, когда не осталось живых сессий, начатых до ухода с
  max (время ухода — в данных плагина).
- **outputStyle** из `~/.claude/settings.json` открытые сессии подхватывают со следующего сообщения. Проект со своим
  стилем (`.claude/settings.local.json`, туда пишет `/output-style`) перекрывает базовый.
- **/model и /effort, набранные во вкладку, Claude Code сам сохраняет как базовые.** Плагин набирает ровно базовые
  значения и модель — так, как она записана (`opus[1m]` остаётся `opus[1m]`, а не превращается в id без 1M).

## Набор во вкладку («Привести», «Проставить базовые всем», «Продолжить»)

Только через cmux (`cmux read-screen`, `send`, `send-key`), только две команды: `/model <id>` и `/effort <уровень>`
(шаблон проверяется перед каждой отправкой), и только в сессию, которая:

- живая и это Claude Code (pid, время старта, путь исполняемого файла). Если `ps` не ответил, плагин не считает
  сессии закрытыми: очередь ждёт, ключ max не трогается;
- с проверенной подписью Claude Code: хаб подтвердил её в своём файле (`verified: true`) или плагин проверил сам —
  `codesign --verify --strict` по исполняемому файлу процесса с тем же требованием, что у хаба (Anthropic, Team ID
  `Q6L2SF6YDW`). `verified: false` от хаба — не набирать, даже если `codesign` согласен;
- привязана к вкладке cmux;
- простаивает (и для «Привести» тоже: со страницы, нарисованной минуту назад, в работающую сессию не набирается —
  отказ `session-busy`), и последняя строка-приглашение `> ` пустая. Любой текст после знака, даже `|`, —
  вкладка пропускается («в поле ввода был текст»).

После набора плагин читает экран ещё раз и ищет ответ Claude Code («Set model to …», «Set effort level to <уровень>»)
**только в новом выводе** — ниже последних строк, что были над полем ввода до набора. Старый такой же ответ на экране не
считается, а уехавший за край окна не мешает. Нет нового ответа — «сессия не подтвердила команду».

«Проставить базовые всем» ставит отличающиеся вкладки в очередь. Свободные набираются сразу. Занятые (работает, ждёт
ответа) — когда освободятся: файл сессии меняется, хаб запускает плагин по `watch`, и плагин набирает отложенное —
**только если хаб сообщает, что он не на паузе** (`AGENTHUB_PAUSED=0`, заявка хабу). Хаб такого не сообщает (старше)
или на паузе — освободившаяся вкладка ждёт кнопки «Продолжить» (действие `apply-continue`, его пауза хаба не пускает).

Очередь и итог — в данных плагина (`PluginData/claude-code/state.json`), страница показывает ход. Обычный запуск и
действия меняют его только под замком `state.lock`: «Остановить» не затирается запуском, одна вкладка не получает
команду дважды. Замок, брошенный убитым запуском (процесса из замка нет), снимается сразу. Перед первой отправкой
пункт сохраняется как «набираю»; если ядро убило запуск посреди набора, этот пункт второй раз не набирается («прервано
при наборе — проверьте вкладку»). Сроки считаются от старта процесса: обычный запуск укладывается в 4 с из 5, действие —
в 26 с из 30, вместе с ожиданием замка и `ps`. «Остановить» снимает отложенные. Повтор —
та же кнопка «Проставить базовые всем»: она берёт вкладки, которые отличаются сейчас.

Без cmux страница только для чтения: кнопок набора нет, есть строка «Без cmux только просмотр». Адаптеры других
терминалов — отдельная задача.

## Действия

| id | уровень | что | отказы `reason=` |
|---|---|---|---|
| `set-model <id>` | immediate | модель для новых сессий (Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1) | `bad-arg` |
| `set-effort <уровень>` | immediate | low, medium, high, xhigh; уход с max | `bad-arg` |
| `effort-max` | confirm-cost | max через `env`; цена в окне — «лимит уходит в разы быстрее, действует сразу во всех вкладках» | — |
| `set-style <имя>` | immediate | стиль из списка (встроенные, свои, плагинов) | `bad-arg`, `unknown-style` |
| `ultracode-on`, `ultracode-off` | immediate | ключ `ultracode` (выключить — удалить ключ) | — |
| `apply <sessionId>` | confirm-cost | «Привести»: набрать во вкладку свободной сессии | `no-cmux`, `no-session`, `session-busy`, `unverified`, `no-tab`, `input-text`, `not-confirmed`, `cmux-failed`, `no-ps` |
| `apply-all` | confirm-cost | «Проставить базовые всем» и «Повторить для K» | `no-cmux`, `nothing-to-do`, `job-running`, `no-ps` |
| `apply-continue` | confirm-cost | «Продолжить»: набрать отложенное во вкладки, которые освободились | `no-cmux`, `no-ps` |
| `apply-stop` | immediate | снять отложенные | — |
| `apply-done` | immediate | убрать итог | — |

Общие отказы: `no-claude`, `settings-broken`, `settings-link-broken` (ссылка `settings.json` ведёт в никуда — плагин
не заменяет её файлом), `settings-unreadable`, `settings-busy`, `not-allowed`, `plugin-busy` (замок состояния держит
другой запуск), `plugin-failed` (сбой самого плагина), `unknown-action`.
Перед `reason=` плагин печатает `message=<объяснение>` на языке хаба (контракт 2).

**Уровни — по правилу реестра** (`docs/contract/plugins-registry.md`): `immediate` — только переключатель, который
ничего не тратит в момент щелчка и отменяется таким же щелчком; будущая цена — словами в `title`. Так устроены модель,
effort ниже max, стиль, ultracode, «Остановить» и «Убрать итог» (у модели, effort и ultracode в подсказке кнопки сказано,
что лимит уходит быстрее). Набор во вкладку из хаба не отменить — «Привести», «Проставить базовые всем» и «Продолжить»
идут через окно с ценой (`confirm-cost`). Max — тоже: окно L из макета стало окном ядра, его «Вы уверены?» — в `cost`.
Линтер реестра отмечает каждое `immediate` для ревьюера.

## Права 1.0.0

| Право | Зачем |
|---|---|
| `fsRead ~/.claude/settings.json` | показать базовые настройки; перечитать перед записью |
| `fsRead ~/.claude/output-styles` | список ваших стилей ответов (только имя из заголовка файла) |
| `fsRead ~/.claude/plugins/installed_plugins.json, ~/.claude/plugins/cache` | стили ответов включённых плагинов Claude Code |
| `fsRead ~/.claude/sessions/*.json` | открытые сессии: pid, папка, имя, состояние, время старта |
| `fsRead ~/.cmuxterm/claude-hook-sessions.json` | в какой вкладке cmux идёт сессия |
| `fsRead ~/.local/bin/claude, ~/.local/share/claude/versions, /opt/homebrew/bin/claude, /usr/local/bin/claude` | установлен ли Claude Code (родная установка, Homebrew, npm; ещё признак — есть `~/.claude/settings.json`) |
| `fsRead $AGENTHUB_CLAUDE_SESSIONS_FILE` | модель и effort открытых сессий от хаба — только метаданные (переменную даёт хаб новее; без неё запись пропускается) |
| `fsWrite ~/.claude/settings.json` | записать выбранное (только белый список ключей) |
| `fsWrite ~/.claude/backups/settings.json.*-agenthub` | копия до каждой правки, хранятся последние 20 |
| `exec /usr/bin/codesign --verify --strict -R …` | перед набором во вкладку: подписан ли процесс сессии Anthropic (то же требование, что у хаба) |
| `exec /bin/ps -o pid=,lstart=,comm= -p …` | жива ли сессия и это ли Claude Code (без аргументов и окружения процесса) |
| `exec …/cmux read-screen\|send\|send-key` | набрать `/model` и `/effort` во вкладку. `read-screen` читает последние 40 строк вкладки: пусто ли поле ввода и появился ли ответ сессии. Текст не сохраняется и не показывается |
| `watch ~/.claude/settings.json`, `~/.claude/sessions/*.json` | показать изменения сразу и набрать отложенное, когда сессия освободилась |

## Что нужно от хаба (заявка 10.11)

1. **`$AGENTHUB_CLAUDE_SESSIONS_FILE`** — модель и effort каждой сессии (метаданные из транскрипта, которые ядро уже
   читает для встроенного claude-sessions). Без него столбцы «Модель» и «Effort» показывают только то, что плагин
   проставил сам, и строку «Модель и effort вкладок покажет хаб новее».
2. **`AGENTHUB_PAUSED=0|1`** всегда (1 — пауза хаба). Действия на паузе ядро и так не пускает; признак нужен
   фоновой очереди. Отложенное плагин набирает сам только при явном `0`: так хаб старше (без признака) никогда не
   получит набор на паузе. Плагин уже это понимает; до выпуска — кнопка «Продолжить».

После выпуска хаба: `node scripts/sync-vendor.mjs`, `watch` на `$AGENTHUB_CLAUDE_SESSIONS_FILE` и при новой версии
контракта — `<agenthub.contract>` с ней.

Тесты: `test/claude-code.test.mjs` (`scripts/check.sh --only claude-code`), синтетический HOME из `fixtures/`, ps и
cmux — двойники.
